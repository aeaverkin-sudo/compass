# ЛОГИКА И МЕХАНИКА — Compass

> Текстовое описание всей бизнес-логики и поведения приложения.  
> Без привязки к конкретной вёрстке — только правила, состояния, потоки данных.

---

## 1. Главный экран — два состояния

### Состояние A — Browse (просмотр)

- QR-код **полностью виден**, фиксирован на фоне (168×168 px, цвет `#C1571F`)
- Карточка (визитка) — **плавающий лист** под QR с отступом 18 px
- Библиотека — **«корешок»** (peek): видна верхняя часть, перекрывает низ карточки на 22 px
- В peek-режиме библиотека показывает **контактные items текущей карточки** (не всю библиотеку)
- Tap по карточке или библиотеке → переход в состояние B

### Состояние B — Library (редактирование библиотеки)

- Карточка **поднимается вверх**, перекрывает нижние 2/3 QR (112 px overlap)
- Карточка становится **компактной** (chips 25 px вместо 32 px)
- Библиотека **раскрывается** под карточкой на всю доступную высоту
- В edit-режиме библиотека показывает **все items глобальной библиотеки**
- У каждой строки — кнопки **+ / −** для включения/выключения item на текущей карточке
- Tap по карточке или библиотеке → возврат в состояние A
- При закрытии edit-режима вызывается `purgeEmptyContactItems()` — удаляются пустые черновики

### Переключение слоёв

- **Только tap** — нет drag handle, нет свайпа вверх/вниз для переключения
- Элементы с атрибутом `data-no-toggle` не триггерят переключение (кнопки, inputs, chips)

## 2. Модель данных: библиотека vs карточка

### Глобальная библиотека (`contactItems[]`)

- Единый список всех контактных строк пользователя
- Каждый item: `{ id, type, label, value, url, order, createdAt }`
- Добавление: кнопка **+** внизу библиотеки → пустая строка в библиотеку (НЕ на карточку автоматически)
- Правило: **только один пустой черновик** одновременно — `addContactItem()` блокируется если черновик уже есть
- Удаление из библиотеки: `deleteContactItem()` — удаляет item и отвязывает от всех карточек
- **Нет кнопки «минус-удалить»** в строках библиотеки — только +/- для карточки

### Привязка к карточке (`card.contactItemIds[]`)

- Массив ID items из глобальной библиотеки
- **+** на строке → `addItemToCard(cardId, itemId)` — item появляется как chip на карточке
- **−** на строке → `removeItemFromCard(cardId, itemId)` — item убирается с карточки, но остаётся в библиотеке
- Порядок chips на карточке = порядок в `contactItemIds[]` (новые добавляются в начало)
- На карточке показываются **только заполненные** items (`isContactFilled`)

### Карточка (`Card`)

```
{
  id, label,                    // внутреннее имя карточки
  displayName,                  // имя на визитке
  photo?,                       // data URL аватара
  title, subtitle, description, location,
  contactItemIds[],             // ссылки на библиотеку
  nextScanAddons[],             // одноразовые дополнения
  sortOrder, createdAt, updatedAt
}
```

## 3. Начальное состояние (empty card)

- Если `displayName` пуст → показывается **только поле ввода имени**
- QR и библиотека **скрыты** до заполнения имени + фото
- QR готов когда: `displayName.trim()` + `photo` установлены (`isCardReady`)

## 4. Детекция типов контактов

### Порядок проверки (`detectContactType`)

1. Пустая строка → `text`
2. MIME `application/pdf` или data URL `data:application/pdf` → `pdf`
3. Email regex → `email`
4. WhatsApp URL (`wa.me`, `whatsapp.com/send`) → `whatsapp`
5. Phone regex (`+?[\d\s()-]{7,}`) → `phone`
6. Telegram URL (`t.me`, `telegram.me`) → `telegram`
7. Instagram (`@handle` или `instagram.com/handle`) → `instagram`
8. **Только полный домен** считается ссылкой — «founder of aded.app» остаётся `text`
9. Расширение `.pdf` → `pdf`
10. Известные хосты: `linkedin.com` → linkedin, `spotify.com` → audio
11. Валидный URL → `website`
12. Fallback → `text`

### Instagram (`parseInstagram`)

- `@handle` → display: `@handle`, url: `https://instagram.com/handle`
- `instagram.com/handle` → то же
- Зарезервированные пути (`p`, `reel`, `stories` и т.д.) → не парсятся

### Telegram (`parseTelegram`)

- `t.me/username` → display: `@username`, url: deep link
- `telegram.me/username` → то же

### WhatsApp (`parseWhatsApp`)

- `wa.me/79001234567` → display: `+7 900 123-45-67`, url: deep link
- `whatsapp.com/send?phone=...` → то же

### PDF

- Определяется по MIME, расширению `.pdf`, data URL
- Хранится как data URL в `ContactItem.value` (макс. 4 MB)
- Прикрепление: long-press на **+** внизу библиотеки, или paste в строку

## 6. Жесты и взаимодействия

### Long-press (700 ms)

| Объект | Действие |
|--------|----------|
| Поле имени / title на карточке | Inline-редактирование |
| Фото на карточке | File picker (камера/галерея) |
| Строка библиотеки (edit mode) | Inline-редактирование value |
| Кнопка **+** внизу библиотеки | File picker для PDF |

- Движение > 10 px отменяет таймер
- `onClick` после long-press подавляется (не срабатывает toggle)

### Swipe горизонтальный

- На области карточки: left/right переключает карточки
- Работает только если `cards.length > 1` и режим browse (не edit)
- Wrap-around: последняя → первая и наоборот
- Порог: 50 px минимум, 60 px для доминирующей оси

### Tap

- Карточка (неинтерактивные зоны) → toggle browse/library
- Библиотека (sheet) → toggle browse/library
- Chip на карточке → открывает url (если есть)

## 7. QR-код

- Размер: 168×168 px
- Цвет: `#C1571F` (terracotta)
- Фон plate: `--qr-plate` (светлый)
- URL в QR: `/share/{token}?pdf=1` (PDF-режим для сканирования)
- Flash-анимация: при изменении карточки/контента инкрементируется `qrFlashKey` → CSS animation 350 ms
- QR **не покрывается** в состоянии A (browse)
- QR **частично перекрывается** карточкой в состоянии B (112 px)

---

## 8. Share (шаринг)

### Создание токена

- POST `/api/share` с `{ portfolio: CardSnapshot, ownerName? }`
- Токен: 12-char nanoid
- Хранение: in-memory Map (теряется при рестарте сервера)

### Авто-синхронизация

- При изменении карточки/библиотеки/addons → POST `/api/share` обновляет snapshot
- Share URL для пользователя: `/share/{token}` (без `?pdf=1`)

### Share button (header)

- Web Share API → fallback clipboard
- Иконка Share, 16 px от safe-top, 24 px слева

### Публичная страница `/share/[token]`

- GET `/api/share/[token]` → CardSnapshot
- Первый просмотр: `markShareViewed()` → инкремент viewCount, доставка nextScanAddons
- Query params: `?print=1` (print view), `?pdf=1` (PDF download)
- Polling статуса каждые 3 сек → очистка nextScanAddons с карточки после доставки

---

## 9. Next Scan — одноразовые дополнения

- Максимум 3 заметки на карточку (`MAX_NEXT_SCAN_NOTES = 3`)
- Типы: `text`, `voice` (mock transcription), `selfie` (camera capture)
- Добавляются через меню NextScan на карточке
- **Доставляются один раз** при первом просмотре share-страницы
- После доставки: `nextScanDelivered = true` → addons не включаются в snapshot
- Карточка очищает addons через polling `/api/share/[token]/status`

---

## 10. Несколько карточек

- Free tier: максимум 2 карточки (`TIER_LIMITS.free.maxPortfolios = 2`)

## 17. Миграция данных (v1/v2 → v3)

Автоматически при rehydrate:

```
contentLibrary[]  →  contactItems[]
portfolios[]      →  cards[]
currentPortfolioIndex  →  currentCardIndex
ContentSlot       →  ContactItem (slotToContactItem)
Portfolio         →  Card (portfolioToCard)
```

Legacy поля в snapshot: `firstName/lastName` → `displayName`, `slots[]` → `items[]`

## 18. Потоки данных (диаграмма)

```
Пользователь вводит текст в строку библиотеки
  → updateContactItem(itemId, { value })
  → detectContactType(value) → type, url, label
  → store обновлён

Пользователь нажимает + на строке
  → addItemToCard(cardId, itemId)
  → contactItemIds.unshift(itemId)
  → triggerQrFlash()
  → chip появляется на карточке
  → POST /api/share (auto-sync)

Кто-то сканирует QR
  → GET /share/[token]?pdf=1
  → markShareViewed() → nextScanDelivered = true
  → CardSnapshot с nextScanAddons (если первый раз)

Polling статуса (3s)
  → GET /api/share/[token]/status
  → nextScanDelivered = true
  → updateCard({ nextScanAddons: [] })
```

## 20. Правила для перезапуска UI

1. **Один элемент за раз** — QR, потом Share, потом Card, потом Library peek, потом Library edit
2. **Pixel-perfect** — сверять с `09-СПЕЦИФИКАЦИЯ-UI.md`
3. **Логику не трогать** — `contact-item.ts`, `messenger-parse.ts`, store actions переносить as-is
4. **Layout с нуля** — не копировать `portfolio-stack.tsx`, absolute positioning переделать
5. **shadcn/Radix** — по правилам `.cursorrules`, не hand-roll UI primitives
